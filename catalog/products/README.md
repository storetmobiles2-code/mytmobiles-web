# Product files

One JSON file per product, named after its URL slug (`samsung-galaxy-a57-5g.json` → `/p/samsung-galaxy-a57-5g`). Product changes go through these files in a pull request, so every change to MRP, details or photos is reviewed and recorded in git history.

The format and its rules live in `src/lib/catalog/product-spec.ts`. In short:

| Field | Notes |
|---|---|
| `status` | `draft` (no change to visibility; new products start hidden), `live` (publish) or `hidden` (unpublish) |
| `variants[].mrp` | MRP in rupees, from the brand's official India listing or the box. Required. |
| `variants[].price` | Selling price in rupees. **Leave it out** for items on the POS stock sheet, because the sheet owns the price. |
| `variants[].stockSheetNames` | Exact item names on the POS stock sheet, so stock imports update this variant |
| `images[]` | Official manufacturer images only, with `sourcePage`, `credit` and `license`. Retailer and marketplace images are rejected. |
| `manufacturerInfo`, `countryOfOrigin` | Legal Metrology declarations, required before a product can go live |
| `sources[]` | Where details, specs, MRP, images and legal details came from, with the date |

Workflow:

```bash
npm run catalog -- new <slug> --brand "Samsung" --name "Samsung Galaxy A57 5G"   # or: export <slug> for an existing product
npm run catalog -- images <slug>      # download + optimise; check .cache/sheets/catalog-<slug>.png by eye
npm run catalog -- validate <slug>
npm run catalog -- apply <slug>       # dry run: shows exactly what will change
```

After review and merge, `apply --write` runs against production; see `docs/agents.md`.

`images.lock.json` is generated by `catalog images`. Don't edit it by hand.
